= JGroups Mongo – `mongo.MONGO_PING`

Project JGroups Mongo provides an implementation of `mongo.MONGO_PING` discovery protocol using MongoDB as a cluster information store.
It uses the official MongoDB driver for Java.

== Installation

=== Maven

For direct usage in JGroups via Maven, use the following coordinates:

[source,xml]
----
<dependency>
    <groupId>org.jgroups.mongo</groupId>
    <artifactId>jgroups-mongo</artifactId>
    <version>1.0.0.Final</version>
</dependency>
----

which pulls in Mongo driver transitively:

[source]
----
org.jgroups.mongo:jgroups-mongo
+- org.jgroups:jgroups
\- org.mongodb:mongodb-driver-sync
   +- org.mongodb:bson
   \- org.mongodb:mongodb-driver-core
      \- org.mongodb:bson-record-codec
----

=== JPMS

The JPMS module name is `org.jgroups.mongo`.

=== WildFly

To provision in WildFly, use the following guide in the https://docs.wildfly.org/41/High_Availability_Guide.html#external-protocols[High Availability Guide → External Protocols].

== Configuration

This library implements a JGroups discovery protocol which replaces protocols such as `MPING` or `TCPPING`.

[source,xml]
----
<mongo.MONGO_PING connection_url="mongodb://localhost:27017/jgroups"
                  remove_all_data_on_view_change="true"
                  return_entire_cache="false"
/>
----

=== Configuration Properties

This protocol extends `JDBC_PING2` and inherits its configuration properties (e.g., `connection_url`, `remove_all_data_on_view_change`, `register_shutdown_hook`).

The following properties are specific to `MONGO_PING`:

[cols="2,1,4",options="header"]
|===
| Attribute | Default | Description

| `collection_name`
| `jgroups-ping`
| Name of the MongoDB collection used to store cluster member information
|===

=== Example Stack

[source,xml]
----
<!--
Based on default tcp.xml with discovery replaced with mongo.MONGO_PING.
-->
<config xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
        xmlns="urn:org:jgroups"
        xsi:schemaLocation="urn:org:jgroups http://www.jgroups.org/schema/jgroups-5.5.xsd">
    <include file="${transport-config:tcp-default.xml}"/>
    <mongo.MONGO_PING connection_url="mongodb://localhost:27017/test"
                      remove_all_data_on_view_change="true"
                      return_entire_cache="false"
    />
    <MERGE3 min_interval="10s"
            max_interval="30s"/>
    <FD_SOCK2/>
    <FD_ALL3 timeout="40s"
             interval="5s"/>
    <VERIFY_SUSPECT2 timeout="1.5s"/>
    <BARRIER/>
    <pbcast.NAKACK2 use_mcast_xmit="false"/>
    <UNICAST3/>
    <pbcast.STABLE desired_avg_gossip="50s"
                   max_bytes="4M"/>
    <pbcast.GMS print_local_addr="true"
                join_timeout="2s"/>
    <MFC max_credits="2M"
         min_threshold="0.4"/>
    <UFC max_credits="2M"
         min_threshold="0.4"/>
    <FRAG2 frag_size="60K"/>
    <pbcast.STATE_TRANSFER/>
</config>
----

=== Programmatic Configuration

The protocol can also be configured programmatically:

[source,java]
----
JChannel channel = new JChannel(
        new TCP(),
        new MONGO_PING()
                .setConnectionUrl("mongodb://localhost:27017/jgroups")
                .setCollectionName("my-ping-collection"),
        new MERGE3(),
        new FD_SOCK2(),
        new FD_ALL3(),
        new VERIFY_SUSPECT2(),
        new BARRIER(),
        new NAKACK2(),
        new UNICAST3(),
        new STABLE(),
        new GMS(),
        new MFC(),
        new UFC(),
        new FRAG2(),
        new STATE_TRANSFER()
);
channel.connect("my-cluster");
----

=== Sharing an Existing MongoClient

By default the protocol creates its own `MongoClient` from `connection_url`.
An application that already has a client (e.g., one managed by Spring) can share it, so that no second client (with its own monitoring threads and connection pool) is created.
Set it after the channel is created and before it is connected:

[source,java]
----
JChannel channel = new JChannel("tcp-MONGO_PING.xml");
MONGO_PING ping = channel.getProtocolStack().findProtocol(MONGO_PING.class);
ping.setMongoClient(mongoClient);
channel.connect("my-cluster");
----

* `connection_url` is still required, it provides the database name.
* A shared client is never closed by the protocol. Close it after the channel: the protocol removes the local member's entry when the channel is disconnected or closed.
* Setting a client after the channel was connected throws `IllegalStateException`.

== Building

This project requires JDK 25 or higher to build.

[source,shell]
----
./mvnw clean install
----

== Testing

Running the automated tests requires a functioning podman or Docker environment.

[source,shell]
----
./mvnw clean verify
----

The project supports running tests with different JDK versions.
To run tests with a specific JDK as runtime, pass the corresponding `javaXX.home` property:

[source,shell]
----
./mvnw clean verify -Djava17.home=/path/to/jdk17 -Djava21.home=/path/to/jdk21 -Djava25.home=/path/to/jdk25
----
